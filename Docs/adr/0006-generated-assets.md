# ADR 0006 — Generated assets

Date: 2026-10-17. Status: accepted.

## Context

The team is the user and the agent; there is no artist. The rule until now was that Unreal
binaries (`.uasset`, `.umap`, textures, meshes) are not edited at all, because Git cannot review
them. That kept materials at the engine's `BasicShapeMaterial` and left the look of the game
(spec 10: PBR parts, sky, clouds, engine plumes, reentry plasma) without anyone to make it.

## Decision

- A binary asset may be committed only as the output of a generator script in `Tools/Assets/`,
  committed together with it. The script is the source: it is reviewed, and running it again
  rebuilds the asset. Nobody edits the binary by hand; to change it, change the script and run
  it. Scripts run headless (Unreal's Python, `UnrealEditor-Cmd -run=pythonscript`, or a
  commandlet) and print what they wrote.
- Part meshes stay procedural C++ (`BuildPartLook`): the drawn shape, the colliding solid, the
  mass and the inertia come from the same data, and a new part needs no asset.
- Materials are few master materials with parameters (colour, metal, roughness, panel lines,
  heat glow), generated by script; textures come from noise inside the materials or from Quixel
  Megascans (free with Unreal, licensed for use in it) for the ground.
- Sky, atmosphere and clouds use the engine's components configured from C++ and `Data/`.
- Effects (plumes, reentry plasma) start as procedural geometry with emissive materials driven by
  the simulation; Niagara systems, if any, are generated by script too.
- The agent judges the result from its own screenshots and leaves the final call to the user.

## Consequences

- The look can improve without an artist, within what procedural, hard-surface modelling does
  well (a clean, stylized look; nothing organic or photographic).
- Generated binaries enlarge the repository; they stay few (master materials, not one per part).
- This lands with M6 (atmosphere and reentry), together with the sky and the effects.
